# 系统教程的编写与审核标准

这份标准整理自本次用户要求，用来检查全部 Go 与 Web 章节。**不能用篇幅、术语数量或“测试通过”替代教学质量。**

| 要求 | 合格时应当看到的内容 | 需要返修的情况 |
| --- | --- | --- |
| 从基础开始，按前置学习 | 一节围绕具体概念；使用新知识前先定义，或链接到已经讲过的章节 | 没讲 HTTP 就写消息头；没讲 JavaScript 就要求理解 DOM、异步或组件 |
| 面向零基础 | 解释名词对应的对象、运行位置和用途；能回答“它是什么、在哪里、为什么用” | 用另一个未知术语解释术语，或把 C++、网络、数据库经验当默认条件 |
| 代码能读懂 | 完整例子有有效注释；正文按执行顺序讲新语法、关键数据和结果 | 只贴代码，或只重复“创建变量、调用函数”而不解释作用 |
| 运行步骤明确 | 写清文件名、目录、工具、保存、启动和停止方式，以及在哪里观察结果 | 只有 `go run .` 或 `npm run dev`，却没有告诉读者在哪个目录、需要哪些文件 |
| 完整程序与片段清楚 | 完整例子可照做；片段说明所属文件、函数、已有变量和完整工程入口 | JSX/SQL/配置片段被当作可独立运行程序；需要数据库却没有环境说明 |
| 结果可观察 | 给出输出或浏览器变化，解释结果如何由输入和代码产生 | 只说“运行看看”“理解即可”，或者把模拟请求说成已监听网络 |
| 练习有反馈 | 先预测，再改一个条件，观察正常和失败表现，最后独立做一个变式 | 只复制代码；参考答案立即展开；故意错误没有对应现象 |
| 知识点就地练习 | 每个知识点解释后直接放可操作的小题、具体输入或修改条件，参考核对紧随题目且默认收起 | 整章只有底部大作业；要求离开正文再找题；参考核对只是重复定义 |
| 每段内容可复制 | 代码、命令、配置、目录结构和预期输出逐块提供按钮；复制正文保留换行与缩进，输出标明“复制输出” | 遗漏输出或折叠答案中的代码；复制混入按钮文字；失败却显示成功 |
| 重要信息易读 | 关键结论、执行前提和容易混淆的区别适量加粗 | 整页加粗、只加粗名词，或用多层卡片和装饰妨碍阅读 |
| 基础、工具与框架相连 | 说明 HTML/CSS/JS、HTTP、Go、数据库、前后端框架各自职责，再做组合项目 | 罗列框架名字，却不解释它解决哪个已经遇到的问题 |
| 不夸大完成情况 | 区分正文阅读、例子运行、工程验收、真实环境和线上发布 | 模板、TODO、外部链接或未执行部署被称作已实现；阅读自动增加完成进度 |

**“前面讲过”必须能找到具体章节，不能只凭作者印象。** 已学基础可以简短回链；新的缩写、方法、参数和运行环境仍要讲清楚。

代码中的注释应帮助跟踪作用、顺序、输入输出和边界。JSON 和预期输出保留合法原文，解释放在正文；命令说明可以放在相邻文字中，避免注释被误复制为输出。

## 独立审核怎样进行

改写者先完成自己负责的全部正文、示例元数据和源文件同步。随后由**未参与这轮写作的新 agent**，逐篇阅读正文、示例和前置章节，对照上表审查。覆盖记录应包含每章判定和具体证据；不能只抽查首页或 HTTP 几节。

发现问题时记录章节、对应段落或代码、缺失知识、为何阻碍零基础读者、具体修复要求。严重知识跳步、不可运行或结果错误必须修复后再审。机械检查只证明文件一致、页面正常和例子实际运行，不能替代独立阅读审核。

## 阅读界面的标准

选择 Go 或 Web 后在左栏选择阶段和章节，目录按页显示；中间一次读一章。目录翻页保留阅读位置、展开内容和助教问题。正文提供本节目录、前置、上一节和下一节。手机能展开目录并选章，不产生横向溢出。
