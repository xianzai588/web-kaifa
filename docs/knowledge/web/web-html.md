# HTML 语义与内容结构：先说明内容是什么

社团网页需要告诉读者：我们是谁、本周活动是什么、如何找到我们。如果只把所有文字放在 div 中，再调大字号，浏览器看不出哪一段是主标题、哪一段是导航。本课先写一张没有 CSS 的介绍页。页面看起来朴素是正常的，目标是让内容结构成立，再在后续课程设计外观。先完成文件与路径练习，知道怎样保存 index.html 并用浏览器打开。

## 把原理一步一步拆开

### 1. 标签、元素和属性
`<p>我们从小程序开始。</p>` 中，p 是标签名，开始标签、文字内容与结束标签组成一个段落元素。元素可以嵌套，例如 main 里面放 h1 和 section；关闭顺序要与打开顺序相反，像先进入房间再打开抽屉，离开时先关抽屉。`id="events"` 是属性，为这个元素提供唯一标识；不是要显示给读者看的正文。HTML 空白和换行多数会被折叠，所以不要用连续空格排版。

#### 就地练习：强调范围与闭合

写一段通知只强调截止时间，圈出开始、结束标签及id属性。

#### 参考核对：强调范围与闭合

先关闭内层再关外层；id放开始标签且唯一，不成为正文文字。

### 2. 文档骨架和正文的分工
doctype 让浏览器使用标准模式；html 的 lang 声明主要语言；head 放字符编码、页面标题等元信息；body 放读者能看到的内容。title 出现在浏览器标签页，h1 出现在页面正文，它们可以关联却不互相替代。meta charset 使用 UTF-8，避免中文因编码解释错误出现乱码。viewport 让手机按自己的视口宽度布局，后续响应式课程会进一步解释。

#### 就地练习：两个标题的位置

只改title、再只改h1，逐次保存刷新记录。

#### 参考核对：两个标题的位置

title改标签页，h1改正文；它们不自动同步。

### 3. 标题层级表达内容关系
本例 h1 表示整页主题，两个 h2 是同级的“本周活动”与“联系方式”。如果活动里还有“周六安排”，它可以使用 h3，而不是为了小字号随便挑一个标题标签。字号交给 CSS 控制。标题像文章目录，读者和辅助技术都能利用它快速定位。列表 ul 表示没有严格顺序的项目，li 表示每项；步骤要求按顺序执行时通常用 ol。

#### 就地练习：为内容选层级

页面主题、两个同级主题、其中一个子主题分别选标题，另为步骤选列表。

#### 参考核对：为内容选层级

依次h1、h2、h3；步骤用ol/li，不按字号随意跳层。

### 4. 页面区域与操作语义
header 容纳页首内容，nav 容纳导航，main 表示主要内容，footer 表示页脚。section 应是一块有主题的内容，一般配标题。它们帮助组织内容，但不会自动产生漂亮布局。a 的 href 用于地址跳转，`#events` 表示定位到本页 id 为 events 的元素。button 用于执行动作，比如展开说明或添加收藏；不应把普通 div 加 click 就当成原生按钮。图片传递信息时 alt 描述它传递的内容，纯装饰图可以空 alt。

#### 就地练习：跳转还是执行

为跳到联系区与展开说明各选原生元素，给前者写一个实际匹配目标。

#### 参考核对：跳转还是执行

跳转用有href的a与对应id，执行用button；语义区块不自动提供布局。

## 在 VS Code 中创建、保存与运行

1. 在自己的练习目录里新建 `web-html` 文件夹，例如放在 `exercises/web/` 下；不要在 materials 原教材中覆盖文件。打开 VS Code，选择“文件 → 打开文件夹”，选中这个新文件夹。
2. 在左侧资源管理器用“新建文件”按下面清单创建文件。带 `/` 的名字表示子文件夹，例如 `assets/style.css` 需要 assets 文件夹，不能把斜杠当普通名字。逐个复制对应完整代码，Windows 用 Ctrl+S，macOS 用 Command+S 保存全部文件。
3. 在 VS Code 资源管理器中右键 index.html，选择“在文件资源管理器中显示”（macOS为Finder），然后双击该文件用浏览器打开。浏览器显示页面，VS Code负责编辑；不要只点编辑器的播放图标，也无需编译HTML。每次修改先保存，再回浏览器刷新。

## 完整可运行示例

### 完整文件：index.html

```html
<!doctype html>
<html lang="zh-CN">
  <head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>社团介绍</title>
  </head>
  <body>
    <header>
      <nav aria-label="页内导航">
        <a href="#events">本周活动</a>
        <a href="#contact">联系方式</a>
      </nav>
    </header>
    <main>
      <h1>周末编程社</h1>
      <p>我们从能运行的小程序开始。</p>
      <section id="events">
        <h2>本周活动</h2>
        <ul>
          <li>周六：制作介绍页</li>
          <li>周日：互相检查页面</li>
        </ul>
      </section>
      <section id="contact">
        <h2>联系方式</h2>
        <p>到学校活动室找我们。</p>
      </section>
    </main>
    <footer>
      <p>这是一份本地练习页面。</p>
    </footer>
  </body>
</html>
```

## 具体结果与解释

```output
浏览器标签页显示“社团介绍”；正文只有一个主标题，下面有两块二级标题和活动列表。点击页首“本周活动”后，地址出现 #events，页面定位到活动区域。
```

从外到内阅读示例：html 包住整个文档；head 描述文档，body 承载正文；header、main、footer 是正文中的同级区域。nav 的 aria-label 为这块导航起名，不替代链接文字。main 的首个 h1 引入整页主题。两个 section 分别用唯一 id 与标题建立分区，导航通过相同 id 找到目标。

请按 Tab 键，焦点会依次移到两个链接；按 Enter 可以执行导航。然后用浏览器开发者工具 Elements 看标签树，折叠和展开 main，确认两个 section 确实在 main 内。这里并不需要 JavaScript，因为浏览器已经提供链接的行为。

## 两种常见问题与排查顺序

### 情况一：点击导航没有定位
检查 href 与 id 是否逐字相同，包含大小写；`href="#event"` 不会自动猜测你想去 `id="events"`。同一页不要写两个同名 id，否则目标有歧义。先定位这个最小差异，再检查是否另有脚本拦截点击。

### 情况二：内容看起来能显示，但标签结构错了
浏览器会尽力修复不合法嵌套，例如把 block 区块放进 p 会使最终树与源码预期不同。“能显示”不是结构正确的证据。用 Elements 对照源码，检查开始与结束标签。VS Code 可以格式化，但格式化不能代替理解结构。另一个边界是用 h1 只为了变大：它可能破坏文章层级，正确做法是给普通文字添加样式。
