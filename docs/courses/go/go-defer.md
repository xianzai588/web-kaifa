# defer 与函数结束时执行

观察延后执行顺序，为资源关闭准备基础。

## 现在登记，离开当前函数前执行

有些操作要在工作结束时做，例如释放已打开的资源。`defer` 是“安排这个调用在当前函数返回前执行”。**它依附当前函数的结束，并不会开启一个后台任务。**

登记时调用参数就确定了，实际调用延后执行。例如变量 n 为 1 时登记 `defer fmt.Println(n)`，随后把 n 改成 2，延后输出仍是登记时的 1。先理解时间顺序，后面的文件、HTTP 再遇到资源清理。

### 就地练习：登记不是马上调用

在defer前后各加一条普通打印，先排列全部输出，再运行。

### 参考核对：登记不是马上调用

普通打印按源码顺序执行；延后调用要到当前函数返回前才执行。

## 参数求值、闭包、关闭错误与 panic

`defer fmt.Println(n)` 在登记时就取到 n 的值；`defer func(){ fmt.Println(n) }()` 的匿名函数体则在返回前才读取 n。后一种需要已经理解 [闭包](go-scope.md)，不要用“defer 都读旧值”概括。

return 先求出返回值，再执行已登记的 defer。命名返回变量可能被 defer 再修改，因此第一次练习建议保持返回路径直观。panic 展开当前 goroutine 的调用栈时也会运行已登记的 defer；`os.Exit` 直接结束进程，不运行它们。

`defer file.Close()` 忽略了 Close 的错误。对于写文件，关闭失败可能表示数据没有完整保存，需要明确检查关闭或 Flush 的结果；不能把“登记了关闭”当作“文件已经可靠写入”。

### 就地练习：登记值与晚读取

令n=1，依次defer fmt.Println(n)与defer func(){fmt.Println(n)}()，然后n=2。预测两条延后输出。

### 参考核对：登记值与晚读取

后登记的闭包先读到2，先登记的普通调用参数已取1，所以输出2、1。

## 先运行一个小例子

在已初始化的独立 Go 练习目录中，把下面完整代码保存为 main.go。本节替换原文件，不在文件末尾追加另一份 main 函数。

```go
package main

import "fmt"

func main() {
	// 现在登记输出操作，等 main 返回前执行，当前不会立即打印。
	defer fmt.Println("最后执行")
	fmt.Println("先执行") // 这是普通调用，执行到这里立即打印。
}
```

在这个目录的终端运行：

```sh
go run .
```

预期输出：

```output
先执行
最后执行
```

## 逐步读懂这个例子

遇到defer时登记调用，main继续打印先执行。main即将返回时执行登记的Println。读文件时通常先确认打开成功，再defer Close。

本例有三个时刻：登记“最后执行”→立即打印“先执行”→main 即将返回，执行登记的打印。输出顺序不等于代码声明的顺序。

多个 defer 后登记的先执行，称为后进先出。在首个 defer 后增加 `defer fmt.Println("第二个登记")`，返回时先处理它，再处理第一个。return 提前结束函数时，已经登记的 defer 仍会执行。

## 自己改一处再运行

再加一个defer打印“第二个登记”，预测三行顺序。

### 参考答案

普通调用立即输出，两个延后调用按后登记先执行。

下面是可直接替换的完整 `main.go`。在本节独立模块中保存后运行 `go run .`。

```go
package main

import "fmt"

func main() {
	defer fmt.Println("最后执行")
	defer fmt.Println("第二个登记")
	fmt.Println("先执行")
}
```

预期结果：

```output
先执行
第二个登记
最后执行
```

## 在循环里关闭文件的真实时机

defer 属于函数，不属于 for 的一轮。若长循环每轮打开文件并 defer Close，所有文件会累积到函数结束才关闭，可能耗尽句柄。把每轮工作放进会及时返回的小函数，或明确关闭并检查错误，再进入下一轮。

### 就地练习：清理属于哪个范围

在纸上比较“循环里defer Close”和“每轮调用小函数，小函数defer Close”。哪个会在下一轮前释放本轮文件？

### 参考核对：清理属于哪个范围

会及时返回的小函数在本轮结束前执行自己的defer；外层循环中的defer累积到整个外层函数返回。

## 用输出验证登记时机

先试两个 defer，预期三行是“先执行”“第二个登记”“最后执行”。再只保留原例子，在普通 Println 之前增加 return：普通输出不再出现，已经登记的“最后执行”仍应出现。

文件关闭的 defer 要在成功取得文件以后登记；打开失败时并没有可关闭的文件。长循环中的 defer 要等整个函数结束，不能误以为每轮结束都会清理。

## 合上参考，独立安排两条返回路径

从空白 main.go 自己写一个带布尔参数的小函数，参数决定是否提前返回。在函数内把整数初值设为1，依次登记两项延后输出：第一项显示“登记值”和当前整数，第二项显示“结束”。随后普通输出“开始”，把整数改为2；若提前返回就普通输出“提前返回”后结束，否则普通输出“继续”和当前整数。

先按登记与执行两个时刻推演，再独立调用两种参数。应分别得到：

| 普通返回路径 | 提前返回路径 |
| --- | --- |
| 开始 | 开始 |
| 继续 2 | 提前返回 |
| 结束 | 结束 |
| 登记值 1 | 登记值 1 |

**两个defer是本次函数自己的清理顺序，不要放到main来替它登记。** 不必用匿名函数或后台任务，本题只用已学函数、条件和defer。

### 参考答案

每次 Run 有自己的 defer。第一项登记时参数已取1，之后 n=2 只影响普通读取；early 为 true 的 return 也会执行已登记的两项。

下面是可直接替换的完整 `main.go`。在本节独立模块中保存后运行 `go run .`。

```go
package main

import "fmt"

func Run(early bool) {
    n := 1
    defer fmt.Println("登记值", n)
    defer fmt.Println("结束")
    fmt.Println("开始")
    n = 2
    if early {
        fmt.Println("提前返回")
        return
    }
    fmt.Println("继续", n)
}

func main() {
	Run(false)
	Run(true)
}
```

预期结果：

```output
开始
继续 2
结束
登记值 1
开始
提前返回
结束
登记值 1
```
