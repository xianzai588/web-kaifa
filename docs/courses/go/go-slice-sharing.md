# 切片共享与复制

观察两个切片共享数据，再用copy建立独立副本。

## 复制描述不等于复制元素

可以把切片描述理解为“从哪一项开始、能看到几项、底层还有多大空间”。`b := a` 复制这些描述信息，底层整数没有重新分配。**给切片变量赋值，不会自动得到可独立修改的全部元素。**

`make([]int,len(a))` 创建新的整数元素空间，长度等于 a 的长度，每项先为 0。`copy(c,a)` 把右侧 a 的元素复制进左侧 c，最多复制两者较短长度的项。要复制全部元素，目标长度必须足够；只预留容量但长度为 0，copy 就没有位置可以写。

### 就地练习：目标只有一项

源为[4 7]，目标make([]int,1)。预测copy返回值和目标内容，修改目标后核对原切片。

### 参考核对：目标只有一项

只复制1项，目标为[4]；目标空间独立，修改它不影响源。copy不会自动扩大目标长度。

## 用满容量表达式限制追加影响

普通切片 `a[low:high]` 会保留从 low 开始的后续容量。完整切片表达式 `a[low:high:max]` 把结果容量限制为 max-low。例如 `view := a[:2:2]` 的长度和容量都为2；对 view 追加新元素需要新的底层空间，避免覆盖 a 中原来第三项。

限制容量不等于复制：在追加前执行 `view[0] = 9` 仍会改到 a[0]。要隔离当前元素就用 make 与 copy。`copy` 返回实际复制数，即源和目标长度的较小者；它也允许源目标范围重叠，适合在已有数组中移动内容。

### 就地练习：限制追加不隔离写入

建立a为[1 2 3]，view:=a[:2:2]，先令view[0]=9，再view=append(view,8)，分别打印a和view。

### 参考核对：限制追加不隔离写入

第一次共享写入使a为[9 2 3]；追加需新空间，view为[9 2 8]，a第三项仍为3。

## 先运行一个小例子

在已初始化的独立 Go 练习目录中，把下面完整代码保存为 main.go。本节替换原文件，不在文件末尾追加另一份 main 函数。

```go
package main

import "fmt"

func main() {
	a := []int{1, 2}
	b := a   // 复制切片描述，两者仍访问相同的整数元素。
	b[0] = 9 // 写入共享数据，所以 a[0] 也会读到 9。
	fmt.Println(a[0])
	// make 创建新元素空间；长度必须足够，copy 才能复制全部项。
	c := make([]int, len(a))
	copy(c, a) // 从右侧 a 复制到左侧 c。
	c[0] = 5   // c 的元素空间独立，不再改变 a。
	fmt.Println(a[0], c[0])
}
```

在这个目录的终端运行：

```sh
go run .
```

预期输出：

```output
9
9 5
```

## 逐步读懂这个例子

b:=a后，b[0]与a[0]对应同一项，修改b会让a看到9。make创建长度与a相同的新空间，copy逐项复制。修改c只影响副本。append是否新分配空间取决于容量，不要靠猜测追加行为判断是否独立。

| 操作后 | a | b | c |
| --- | --- | --- | --- |
| `b := a` | [1 2] | [1 2]，与 a 共享 | 尚未创建 |
| `b[0] = 9` | [9 2] | [9 2] | 尚未创建 |
| make 后再 copy | [9 2] | [9 2] | [9 2]，独立元素空间 |
| `c[0] = 5` | [9 2] | [9 2] | [5 2] |

本例的元素是普通整数，逐项复制后就是独立数据。后面若切片元素里还包含指针、map 或切片，copy 不会递归复制它们指向的所有内容，需要重新考虑共享层级。

## 自己改一处再运行

修改a[1]后打印a、b、c，指出谁互相影响。

### 参考答案

c 复制时第二项还是2。之后 a[1] 的写入也会从 b 读到，c 自己的第二项保持2。

下面是可直接替换的完整 `main.go`。在本节独立模块中保存后运行 `go run .`。

```go
package main

import "fmt"

func main() {
	a := []int{1, 2}
	b := a
	b[0] = 9
	c := make([]int, len(a))
	copy(c, a)
	c[0] = 5
	a[1] = 8
	fmt.Println(a, b, c)
}
```

预期结果：

```output
[9 8] [9 8] [5 2]
```

## “复制了”还要问复制到哪一层

整数元素的 copy 能隔离本课修改。若元素是切片或含指针的结构体，copy 只复制元素中的描述或地址，指向的数据仍可能共享。排查备份被修改时，逐层确认谁持有同一个底层对象，不要仅凭调用过 copy 就断定完全独立。

### 就地练习：画出两层共享

假设元素改成切片：a:=[][]int{{1}}，b用make与copy复制外层。预测b[0][0]=9后a[0][0]，用已有切片知识解释。

### 参考核对：画出两层共享

a也读到9；外层元素保存内层切片描述，copy没有重建内层整数空间。

## 验证 copy 的目标长度

`make(切片类型, 长度, 容量)` 可以提供第三个参数，表示预留的容量；省略第三项时，容量与长度相同。因此 `make([]int,0,len(a))` 的长度是 0，容量才是 len(a)。**容量表示可容纳的空间，不表示已经存在那么多可以下标读取的元素。**

把 c 的创建改成 `make([]int,0,len(a))`，然后打印 `copy(c,a)` 的返回值与 len(c)。它们应都是 0；此时访问 c[0] 会越界，先删去该访问再运行。恢复 `make([]int,len(a))` 后复制项数为 2。

再把 a[1] 改成 8，同时打印三者：a、b 的第二项都变为 8，c 仍为 2。不要靠观察 append 一次碰巧怎样来证明永远共享或永远独立。

## 合上参考，独立建立可修改的副本

从空白 main.go 建立一份整数记录，自己使用 make 与 copy 准备独立备份，不用普通切片赋值代替元素复制。这个任务直接写在 main 中即可，不要求新的切片返回函数。

复制完成后，若原记录非空，把原记录第一项改为9，把备份最后一项改为50，然后打印两组数据。先预测，分别验收：

| 复制前的原记录 | 最后原记录 | 最后备份 |
| --- | --- | --- |
| 空记录 | [] | [] |
| [4] | [9] | [50] |
| [4 7] | [9 7] | [4 50] |

**空记录不能访问首项或末项；两项案例要证明修改两边都不会传到另一边。** 保存每种输入的实际结果，并解释目标长度为何要足够。

### 参考答案

目标长度等于原长度，copy 才覆盖全部元素。空初值会跳过两次下标访问，得到两行 []；初值 [4] 得到 [9] 和 [50]，证明只有一项时两份数据仍独立。

下面是可直接替换的完整 `main.go`。在本节独立模块中保存后运行 `go run .`。

```go
package main

import "fmt"

func main() {
	original := []int{4, 7}
	// 目标必须有实际长度，只有容量而长度为0时copy不会复制任何元素。
	backup := make([]int, len(original))
	copy(backup, original)
	if len(original) > 0 {
		original[0] = 9
		backup[len(backup)-1] = 50
	}
	fmt.Println(original)
	fmt.Println(backup)
}
```

预期结果：

```output
[9 7]
[4 50]
```
