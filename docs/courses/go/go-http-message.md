# HTTP 请求与响应

先知道谁向谁索取什么，再辨认地址、方法、状态、头部和正文。

## 浏览器和 Go 程序分别在做什么

你在浏览器输入网址、按回车，浏览器会向那个地址索取内容。浏览器是**客户端**：它主动发出请求。另一个正在运行的程序接到请求，准备内容再回复，它在这次交流中是**服务器端**。服务器可以是自己的 Go 程序，也可以是别人的程序；它不一定是一台专用机器。同一台电脑可以同时运行浏览器和服务器程序。

**HTTP 是客户端和服务器交换请求与响应的一套规则。**“协议”就是双方约定怎样表达信息。HTTP 的英文全称是 Hypertext Transfer Protocol，常用于获取网页、图片和发送表单数据。这里先学读规则，下一节才让 Go 程序真正接收浏览器请求。

```text
浏览器（客户端）  -- 请求：我要 /hello -->  Go 程序（服务器端）
浏览器（客户端）  <-- 响应：200，Hello --  Go 程序（服务器端）
```

请求是“我要做什么”，响应是“结果如何、内容是什么”。一次打开网页可能产生很多次请求：先取 HTML，再取它引用的 CSS、图片和脚本。浏览器负责显示，Go 程序负责接收请求和准备响应。

### 就地练习：网页不止一次请求

打开任一有独立CSS的本地页面，在Network分别找到HTML与CSS请求。写出每次谁是客户端、谁是服务器。

### 参考核对：网页不止一次请求

浏览器对每个资源主动请求，提供资源的程序回复；同一页面通常对应多次请求。

## URL：先把一个地址拆开

URL 是资源地址。例如：

```text
http://127.0.0.1:8080/hello?name=Go
```

| 部分 | 本例的值 | 先记住什么 |
| --- | --- | --- |
| 协议方案 | `http` | 按 HTTP 规则通信；`https` 还保护传输过程 |
| 主机 | `127.0.0.1` | 回环地址，表示当前这台电脑；不是另一台电脑 |
| 端口 | `8080` | 这台电脑上目标服务监听的数字入口 |
| 路径 | `/hello` | 向服务索取哪个资源，不一定是磁盘上的文件 |
| 查询参数 | `name=Go` | `?` 后的附加输入；多个参数用 `&` 分开 |

同一台电脑上，网站预览可能在 8743 端口，你的 Go 服务在 8080 端口。访问错端口，就找错了程序。**在手机上输入 `127.0.0.1`，指向的是手机自己，不是你的电脑。** 路径和查询参数也不是一回事：`/hello` 决定找哪个处理入口，`name=Go` 是传给它的数据。

有些 URL 末尾还有 `#章节名`。这个片段通常由浏览器处理，不随 HTTP 请求发给服务器；本站的 `#/learn/...` 是网站自身的页面导航。

拆分http://127.0.0.1:8080/hello?name=Go#intro，写出路径、参数、片段。手机上的同一回环地址会找谁？

### 参考核对：片段会到服务器吗

路径/hello，参数name=Go，片段intro通常留在客户端；手机的127.0.0.1指向手机自己。

## 方法表达操作，状态表达结果

请求还带有“方法”。先认识常见四种，不要求现在就实现它们：

| 方法 | 常见用途 | 例子 |
| --- | --- | --- |
| `GET` | 获取内容 | 查询 `/hello` 或一条记录 |
| `POST` | 提交数据或创建资源 | 提交新活动 |
| `PATCH` | 修改资源的一部分 | 只改活动标题 |
| `DELETE` | 删除资源 | 删除某条活动 |

浏览器地址栏适合发 GET。把网址改成 `/delete` 并不会自动变成 DELETE 方法；操作的真实规则由服务器的接口约定决定。

响应中的**状态码是服务器对处理结果的数字说明**。本阶段先会认：200 成功并通常有正文；201 创建完成；204 成功但没有正文；400 输入不符合要求；404 找不到目标；405 路径存在但方法不支持；500 服务内部处理失败。收到 400 或 404，也可能已经成功连接服务器，只是处理结果不是成功。

### 就地练习：响应失败还是连接失败

将“服务器返回404”和“停止服务后连接被拒绝”分开解释。地址栏改为/delete是否产生DELETE请求？

### 参考核对：响应失败还是连接失败

404是收到HTTP响应但资源不存在；连接被拒绝尚未得到该响应。地址栏导航仍是GET，路径文字不决定方法。

## 头部和正文最后再看

请求和响应都可以带头部与正文。**头部提供附加说明，正文装实际内容；请求头与响应头分别属于两个方向。** 例如请求头 `Accept: application/json` 表示客户端希望得到 JSON；响应头 `Content-Type: text/plain; charset=utf-8` 表示服务器实际发送的是 UTF-8 文本。`Content-Type` 不是放进 JSON 里的业务字段，也不是每次请求都由客户端设置。

用 HTTP/1.1 的文字形式看一对简化消息：

```http
GET /hello?name=Go HTTP/1.1
Host: 127.0.0.1:8080
Accept: text/plain

```

```http
HTTP/1.1 200 OK
Content-Type: text/plain; charset=utf-8

Hello Go
```

第一行说方法、路径或状态；中间是头部；空行之后才是正文。本例 GET 没有请求正文，响应正文是 `Hello Go`。HTTP/2 等版本在网络上传输的编码不同，这里用容易读的形式理解相同含义。不用手工给浏览器拼这些文字。

### 就地练习：格式放在哪里

为返回JSON列表写出响应Content-Type与正文各自内容。客户端Accept不同，服务器是否就已自动转换格式？

### 参考核对：格式放在哪里

头部为application/json，正文是JSON文字。Accept表达偏好，实际响应由服务器实现决定。

## 在 Go 里观察一个请求对象

在已经初始化的独立 Go 练习目录，把完整代码保存为 `main.go`，替换原文件。模块建立方法见 [第一节](#/learn/go/go-vscode)，不要在仓库根目录运行 `go mod init`。

```go
package main

import (
	"fmt"
	"net/http"
)

func main() {
	// NewRequest 只整理请求数据；这里没有启动服务，也没有发送请求。
	// GET 是方法，完整 URL 是目标地址，nil 表示本例没有请求正文。
	req, err := http.NewRequest("GET", "http://127.0.0.1:8080/hello?name=Go", nil)
	if err != nil {
		fmt.Println("请求地址不合法：", err)
		return
	}

	// req 保存请求；URL 保存拆好的地址，Path 只取路径部分。
	fmt.Println(req.Method, req.URL.Path)
	// Query 得到查询参数，Get("name") 读取 name 对应的字符串。
	fmt.Println(req.URL.Query().Get("name"))
}
```

在此目录终端运行：

```sh
go run .
```

输出：

```output
GET /hello
Go
```

`net/http` 是 Go 标准库包，像前面的 `fmt` 一样需要导入。`req` 的类型是 `*http.Request`，指向保存请求信息的结构体。`req.URL` 又指向地址对象，点号让我们访问其字段或方法。`Query().Get(...)` 是连续两次方法调用；返回值是字符串，不会因为文字是 `10` 就变成整数。

**即使 8080 上没有任何服务，这个例子也能输出成功，因为它从未访问网络。** 真正发送要调用客户端；真正接收要启动监听，下一节实现后者。

## 自己改一处再运行

先把 URL 改为 `http://127.0.0.1:8080/add?a=10&b=20`，让程序打印路径、a 和 b。再故意把主机改成 `http://[bad`，观察错误分支。解释正常输出能证明什么、不能证明什么。

### 参考答案

查询值仍是字符串。改地址为http://[bad会在构造时失败；这份程序没有Do或服务监听，成功只证明请求对象可构造，不能证明端口有服务。

下面是可直接替换的完整 `main.go`。在本节独立模块中保存后运行 `go run .`。

```go
package main

import (
    "fmt"
    "net/http"
)

func main() {
	req, err := http.NewRequest("GET", "http://127.0.0.1:8080/add?a=10&b=20", nil)
	if err != nil { fmt.Println(err); return }
	fmt.Println(req.URL.Path, req.URL.Query().Get("a"), req.URL.Query().Get("b"))
}
```

预期结果：

```output
/add 10 20
```

## 请求真正发出去还需要客户端

NewRequest只组装方法、URL、头和可选正文，http.Client.Do才会尝试发送。真实客户端要设置超时、传入context、检查网络错误和状态码，并在取得响应后关闭Body；HTTP404通常不是Do返回的网络error。

URL中的scheme决定协议，host可含端口，path选资源，query传参数，fragment是客户端片段通常不发送给服务器。HTTPS为传输提供加密与服务器身份验证，但不能替代业务权限检查。GET用于获取资源，POST通常用于提交，PUT/PATCH/DELETE各有合同；“方法名称正确”不代表服务器已经实现该操作。

构造仍成功，说明只解析和组装对象。Client.Do才尝试通信，且仍要检查网络错误、状态和关闭Body。
