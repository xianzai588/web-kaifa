# 用 VS Code 编辑和运行 Go

分清文件、终端和工具链，亲手保存并运行一次。

## 先认清三个工具的职责

源码是你写的程序文字，通常保存在 `.go` 文件里。VS Code 让你编辑和保存文字；Go 工具链负责检查、编译和运行；VS Code 的 Go 扩展帮助补全、导航和提示错误。

**安装 Go 扩展不会替你安装 Go，打开一个文件也不等于运行程序。** 先按 [Go 环境安装](../../../index.html#/setup?topic=go) 安装与你的系统匹配的 Go 工具链。打开 VS Code 的“终端 → 新建终端”，输入下面命令并按 Enter：

```sh
go version
```

终端应显示以 `go version go` 开头的版本、系统和处理器信息。具体补丁版本会变化；本教程的独立例子使用 Go 1.22 及以上的基础语法。如果显示找不到命令，先回环境课检查安装和 PATH，再彻底退出并重新打开 VS Code。

### 就地练习：把工具与现象配对

只装 Go 扩展但终端找不到 go，该检查哪个工具？已有 main.go，点保存后没有输出，还缺哪一步？先写下两条判断，再在自己的终端核对 `go version`。

### 参考核对：把工具与现象配对

找不到 go 先查 Go 工具链与 PATH；保存只更新源码，还需在该目录主动运行。`go version` 成功也不表示你的程序已经执行。

## 用一个独立文件夹放本次练习

在文件管理器中新建 `hello` 文件夹，用 VS Code“文件 → 打开文件夹”打开它。若你就在本学习仓库练习，请放在 `exercises/go/hello`，**不要在整个资料仓库根目录初始化 Go 模块**。

左侧资源管理器显示 hello，才是打开了文件夹。用“终端 → 新建终端”打开这个文件夹里的终端，核对当前位置：PowerShell 输入 `Get-Location`，cmd 输入 `cd`，macOS/Linux 输入 `pwd`。结果的末尾应是你的 hello 文件夹。

新独立目录在终端执行一次：

```sh
go mod init example.com/learn/hello
```

`go mod init` 为本目录创建模块说明文件 `go.mod`；`example.com/learn/hello` 是练习的模块名字，不是要求你访问或购买一个网站。已经有 go.mod 的目录不用重复初始化。第一次成功后，左侧应出现 go.mod。

### 就地练习：核对两份目录

在 hello 外新建 scratch 文件夹，只切换终端目录，不移动文件。检查 scratch 是否有 go.mod；说明此时为什么不能把 hello 的运行结果算作 scratch 的结果。

### 参考核对：核对两份目录

模块和源码属于具体目录。scratch 为空时没有可运行的 main 包；回到 hello 才能运行原程序，新练习应独立初始化。

## 保存一份真正的 main.go

在左侧资源管理器中点“新建文件”，填写 `main.go`。将下面完整程序放入编辑区，按 `Ctrl+S`（macOS 使用 `Cmd+S`）保存：

```go
package main

import "fmt"

func main() {
	// 用 Go 的打印工具，在终端显示这一句文字。
	fmt.Println("你好，Go")
}
```

这里只要知道花括号里的打印会执行；`package`、`import`、`func` 和括号的含义，下一节 [Go 程序结构](../../../index.html#/learn/go/go-program) 会逐行讲。文件夹现在至少有两个文件：

```text
hello/
  go.mod
  main.go
```

**程序代码放 main.go，启动命令输入终端，两者不能互相粘贴。** 终端里的提示符不是命令的一部分，不要复制提示符或网页的代码框标记。

### 就地练习：分开代码和命令

在纸上把 `package main`、`go run .`、`你好，Go` 分配到“源码文件、终端命令、预期结果”。再检查 main.go 中是否只保存源码。

### 参考核对：分开代码和命令

package 行属于 main.go；go run . 在终端执行；问候文字是输出。不要把网页的输出框内容追加进源文件。

## 主动运行，再看真实输出

终端保持在 hello 目录，执行：

```sh
go run .
```

末尾的点代表当前目录。Go 读取这个目录的源码，检查并运行；正常结果为：

```output
你好，Go
```

这个程序输出一行后就结束，终端重新出现可输入命令的位置。它不会因为你之后编辑文字就自动再次运行。

把引号里的文字改为“我保存了新代码”，先预测输出，再保存、重新运行。若仍显示旧句子，检查正在保存的文件和终端当前位置是不是同一份练习。

## Go 扩展此时能帮什么

扩展面板搜索 Go，核对发布者 Go Team 和标识 `golang.go` 后安装。打开 .go 文件，按提示安装语言工具；输入 `fmt.` 可观察补全，光标停在 Println 上可看说明。

这些工具帮助编辑，但真正的运行结果仍来自终端。测试与 F5 断点等到学过函数后再学，[VS Code 工具图文](../../../index.html#/setup?topic=editor&step=tools) 提供后续操作入口。

### 就地练习：没有补全能否运行

暂时不用自动补全，手写完整的 fmt.Println 调用并保存运行。记录终端结果，判断补全是否是 Go 执行的必要条件。

### 参考核对：没有补全能否运行

语法与工具链正确就能输出问候；补全帮助编辑，不参与程序入口的执行。

## 按现象定位问题

| 现象 | 原因检查 | 验证 |
| --- | --- | --- |
| `go.mod file not found` | 终端是否在 hello；本独立目录有没有初始化 | 当前目录下找到 go.mod 后再运行 |
| 找不到 .go 文件 | 是否真的保存为 main.go，是否保存到 hello | 资源管理器中能看到文件 |
| 语法错误和行号 | 引号、括号、名称是否与完整程序一致 | 修复后得到问候输出 |
| 运行持续不结束 | 当前程序是否已被改成等待输入或循环 | 必要时 Ctrl+C 中止，再核对源码 |

### 参考答案

`go run .` 读取磁盘上的 main.go。输出没变时，先核对保存状态与终端所在目录，而不是重新安装插件。

下面是可直接替换的完整 `main.go`。在本节独立模块中保存后运行 `go run .`。

```go
package main

import "fmt"

func main() {
	fmt.Println("我保存了新代码")
}
```

预期结果：

```output
我保存了新代码
```

## 合上步骤，独立准备第二份练习

**这次只允许取用本节最小源码，打开目录、初始化、保存和运行都由你独立完成。** 在另一个位置建立名为 hello-again 的独立文件夹，不复制原来的 go.mod；模块名称使用 example.com/learn/hello-again。将输出文字定为“第二份练习”，完成后把原 hello 和新目录同时留在电脑上。

自查四项：新目录有自己的 go.mod 与 main.go；终端当前位置是 hello-again；主动启动后输出“第二份练习”；程序结束后终端能继续输入命令。

再制造一次未保存问题：运行成功后只编辑为“新目录的新内容”而暂不保存，重新运行应仍输出旧句子。自行定位原因，再保存运行；新结果应只有“新目录的新内容”。记录终端实际目录和这两次输出，不能回到原 hello 改一句来代替第二份独立练习。

### 参考答案

在文件管理器创建 hello-again 后，用 VS Code 打开它，并在该文件夹终端执行一次：

```sh
go mod init example.com/learn/hello-again
```

main.go 的完整内容：

```go
package main

import "fmt"

func main() {
    fmt.Println("第二份练习")
}
```

执行 `go run .` 应显示“第二份练习”。接着只在编辑器把文字改成“新目录的新内容”，暂不保存，再运行仍显示“第二份练习”；保存后再次运行才显示新句子。若启用了自动保存，先临时关闭自动保存再做这个实验。最后检查 go.mod 第一行为 `module example.com/learn/hello-again`，原 hello 的文件应仍在原位置。

参考：[Go 官方模块教程](https://go.dev/doc/tutorial/create-module)、[VS Code Go 文档](https://code.visualstudio.com/docs/languages/go)。
