# 常量与变量的区别

用 const 表达固定规则，用变量表达会变化的数量。

## 规则固定，数据可变

**常量的值在这份程序中固定，变量的值允许被赋值更新。** `passScore` 表达本练习约定的及格线；`score` 表达某一次成绩。把及格线起一个名字，后面的比较就不必重复猜测数字 60 代表什么。

这一节第一次用到 `>=`，读成“大于或等于”：`75 >= 60` 为 `true`，`59 >= 60` 为 `false`。它只产生一个判断结果，不修改成绩，也不输出“及格”文字；下一课学习全部常用运算符，条件课再根据结果选择动作。

### 就地练习：分开规则与输入

为“每组固定4人、目前报名9人”选择 const 或变量。写两次输出，把报名数改为10，固定值保持不变。

### 参考核对：分开规则与输入

每组人数用 const，报名人数用变量；两次固定值都是4。规则是否固定取决于本题约定，不取决于值是不是数字。

## 常量分组、类型与 iota

常量表达式在编译时可确定，可包含数字、字符串、布尔值及适用的运算。`const total = 2 * 30` 合法；从终端读取的结果不能用 const 保存。无类型常量如 `const limit = 60` 在使用处按上下文确定适合的类型；`const limit int = 60` 则已有明确的 int 类型。

下面的声明放在 main 里可直接试验：

```go
const (
    Draft = iota // 第一行是 0。
    Published    // 省略表达式时沿用上一行，iota 在下一行变成 1。
    Archived     // 2。
)
fmt.Println(Draft, Published, Archived) // 0 1 2
```

iota 在每个 const 声明组从 0 开始，按组中常量声明行递增，不是运行时自增变量。同一行定义多个名字会取得同一行的 iota 值。它能给状态编号，但这些名字仍是普通常量，并不会自动拒绝输入 99；业务输入校验要另外写。

更改持久化状态编号可能让旧数据库记录被误读。需要长期保存或对外传输的编号时，明确写出固定数值，比依赖插入行后会变化的序号更安全。

### 就地练习：在组中插入一行

复制 iota 声明，在 Draft 与 Published 之间插入 Pending 一行，再打印四个名字。预测哪些编号会改变。

### 参考核对：在组中插入一行

依次是0、1、2、3，Published 与 Archived 的编号都后移。已持久化的状态编号不应随插行改变。

## 先运行一个小例子

在已初始化的独立 Go 练习目录中，把下面完整代码保存为 main.go。本节替换原文件，不在文件末尾追加另一份 main 函数。

```go
package main

import "fmt"

func main() {
	// 及格线是本练习固定的规则，const 不允许运行中重新赋值。
	const passScore = 60
	score := 75 // 本次成绩是变量，可以在源码中改成其他分数再运行。
	fmt.Println(passScore)
	// >= 询问“成绩是否大于或等于及格线”，结果是布尔值。
	fmt.Println(score >= passScore)
}
```

在这个目录的终端运行：

```sh
go run .
```

预期输出：

```output
60
true
```

## 逐步读懂这个例子

passScore 固定为 60。score 是 75。`>=` 比较左边是否大于或等于右边，结果是布尔值 true。这个结果可以打印，也可以在后面的条件语句里使用。

第一行输出固定规则 60。第二行先读取 score 和 passScore，再做比较，最后把比较结果交给 Println。把成绩改成 59，规则仍为 60；把常量声明中的 60 改成 70 并重新运行，则是改写了程序的规则。

`const course = "Go"` 也可声明文字常量。常量不是“绝对永远不能改的文件”，它禁止的是在程序运行逻辑里给这个常量再赋值。

## 自己改一处再运行

只把 score 改成 59，再运行；然后改成 60。

### 参考答案

59 < 60，所以第二行是 false；将 score 改成 60，第二行变为 true。

下面是可直接替换的完整 `main.go`。在本节独立模块中保存后运行 `go run .`。

```go
package main

import "fmt"

func main() {
	const passScore = 60
	score := 59
	fmt.Println(passScore)
	fmt.Println(score >= passScore)
}
```

预期结果：

```output
60
false
```

## 哪些值不能声明成常量

`const numbers = []int{1,2}` 不合法；切片将在后续学习，它的内容不能这样声明成常量。`const n = 输入函数()` 一般也不合法，因为常量不能依赖运行时的输入。需要运行中改变的配置用变量；固定的规则值才使用 const。

### 就地练习：运行时输入能否固定

判断 `const n = 2*3` 与“把用户输入保存到 const”哪一种成立，并说明失败发生在编译还是输入阶段。

### 参考核对：运行时输入能否固定

常量表达式2*3可在编译时确定；用户输入只在运行时得知，不能用于这样的 const 声明。

## 观察不能重新赋值的含义

在常量声明后增加 `passScore = 70`，保存运行，应看到不能赋值给常量的编译错误。删除这行，再把声明本身改为 `const passScore = 70`，程序可以运行。这两次都实际验证后，用一句话说明区别。

成绩依次用 59、60、61；预期判断结果依次是 false、true、true。**包含临界点的实验能够检验 `>=` 是否写对。**

## 合上参考，区分自己的规则和数据

从空白 main.go 表示“固定目标为 30 分钟，本次计划为 29 分钟”。自己命名目标与计划，选择常量或变量来保存它们，并各打印一行。暂时不写分支、循环或复杂比较，本题只验收声明选择。

将本次计划依次设为 29、30、31，分别运行；第一行应始终为 30，第二行分别为 29、30、31。再试在运行逻辑里给目标重新赋值，确认编译拒绝；删除错误赋值，把目标声明本身改为 40，重新运行才会显示新目标。

**独立说明“固定规则”与“允许更新的数据”，不要只沿用 passScore 和 score。**

### 参考答案

targetMinutes 表示固定规则，plannedMinutes 表示本次输入。把 plannedMinutes 的初值分别改为 30、31，第一行都保持 30。临时加 targetMinutes = 40 会编译失败；把声明本身改为 const targetMinutes = 40 后再运行，第一行才是 40。

下面是可直接替换的完整 `main.go`。在本节独立模块中保存后运行 `go run .`。

```go
package main

import "fmt"

func main() {
	const targetMinutes = 30
	plannedMinutes := 29
	fmt.Println(targetMinutes)
	fmt.Println(plannedMinutes)
}
```

预期结果：

```output
30
29
```
