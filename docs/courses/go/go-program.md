# Go 程序结构

看懂 package、import、main 和一条打印语句，运行后得到一行文字。

## 先分清“源码、编译、运行、输出”

源码是你写给 Go 工具看的文字，保存在 `.go` 文件里。编译会先检查语法和名字，把正确的源码变成机器能够执行的程序。运行才会真正执行里面的语句。终端里的输出是程序产生的结果。

**写好代码并保存，才算改好了要运行的文件；网页里的代码示例不会替你在电脑上执行。** 本课只需要上一节准备好的独立文件夹、`go.mod` 和终端。

`main.go` 的文件名与 `func main()` 的函数名是两回事。前者方便我们找到源码，后者是 Go 规定的可执行程序入口。现在照着保留 `package main` 和 `func main()`，后续学函数和包时再展开它们的组织方式。

给“保存 main.go、构建成功但无问候、启动后显示问候、终端报语法错误”分别标出所在步骤。哪个能证明打印语句执行过？

依次对应编辑保存、编译构建、运行输出、编译失败。只有实际问候输出能证明对应调用执行过。

## 一个包为什么可以有多个文件

`main.go` 是约定的文件名，并非入口的特殊开关；同目录的 `hello.go` 也可以声明 `package main`。在同一个 main 包中只能有一个入口 `func main()`，它不带参数、也不声明返回值。后续把函数拆到多个文件时，用 `go run .` 运行整个包；`go run main.go` 只选定命令中列出的文件，可能漏掉另一个文件里的函数。

| 终端命令 | 做什么 | 本节会看到什么 |
| --- | --- | --- |
| `go run .` | 编译当前包并立即运行 | 显示问候，程序结束 |
| `go build -o hello-app .` | 生成可执行文件 | 成功时通常不打印问候 |
| `go fmt ./...` | 格式化当前模块中的源码 | 改善排版，不执行打印 |

第二条命令是选学：Windows 使用输出名 `hello-app.exe`，在 PowerShell 用 `./hello-app.exe` 启动；macOS/Linux 用 `./hello-app`。构建成功与程序被运行是两个可分别观察的步骤。

### 就地练习：改名是否改变入口

把本节唯一的 main.go 改名 hello.go，保留内容，用 go run . 运行。随后改回文件名；解释为什么问候没有改变。

### 参考核对：改名是否改变入口

目录中仍是同一个 main 包和唯一的 func main；源码文件名不决定入口，运行整个包仍显示同一句问候。

## 先运行一个小例子

在已初始化的独立 Go 练习目录中，把下面完整代码保存为 main.go。本节替换原文件，不在文件末尾追加另一份 main 函数。

```go
// main 包告诉 Go：这里是一个可执行程序。
package main

// fmt 是 Go 自带的输出工具；引入后才能使用 fmt.Println。
import "fmt"

// 程序启动后进入 main，依次执行花括号里的语句。
func main() {
	// 括号内的字符串是输出内容，Println 会在末尾换行。
	fmt.Println("你好，Go")
}
```

在这个目录的终端运行：

```sh
go run .
```

预期输出：

```output
你好，Go
```

## 逐步读懂这个例子

1. `package main` 表明这个文件属于可执行程序使用的 main 包。
2. `import "fmt"` 引入 Go 自带的 fmt 包；本例用它在终端输出文字。
3. `func main()` 定义入口函数。`func` 表示定义函数；括号后的花括号包住入口内的语句。
4. `fmt.Println("你好，Go")` 调用打印函数。点号连接包名和函数名，括号里是要打印的内容，双引号表示字符串。
5. Println 打印后换行。程序结束，终端再次出现提示符。

执行时可以用手指按这个顺序跟读：进入 `main` → 调用 `fmt.Println` → 显示文字并换行 → 离开 `main`。`import` 让打印工具可用，但它本身不打印内容。

括号内的内容叫这次调用的**参数**，也就是交给函数处理的数据。这一课只传一段文字；参数为什么可以是数字、函数怎样返回结果，后面的课程会分别讲。

## 从编译错误找到对应行

| 现象 | 原因 | 修复和复验 |
| --- | --- | --- |
| `"fmt" imported and not used` | 导入了 fmt 却删掉了所有使用它的语句 | 保留需要的打印，或删去不需要的导入 |
| `main redeclared` | 同一包中放了两份 main 函数 | 本课替换旧文件内容，只保留一份入口 |
| `package ... is not a main package` | 当前包声明不是 main | 检查运行目录和 package 行 |

先读错误给出的文件和行号，再检查它附近的代码；末尾括号缺失时，报错位置可能在下一行。修复后应同时满足编译成功与输出正确。

### 就地练习：定位未使用的导入

在原程序副本中注释唯一的 fmt.Println，保留 import。先预测会得到空输出还是编译错误，再运行并恢复。

### 参考核对：定位未使用的导入

应先报 fmt 未使用，程序尚未运行。恢复调用后才显示问候；单纯“没输出”不能判断执行到了哪里。

## 保存、运行与报错自检

| 看到什么 | 先检查什么 | 修复后怎样验证 |
| --- | --- | --- |
| 还是输出旧文字 | `main.go` 是否已按 `Ctrl+S` 保存；终端是否在这份文件的目录 | 再运行 `go run .`，核对新句子 |
| `undefined: fmt` 或 `undefined: fmt.println` | 是否引入 `"fmt"`；`Println` 的 P 是否大写 | 恢复完整例子再运行 |
| `expected ...` 一类语法错误 | 报错行附近的英文引号、圆括号、花括号是否配对 | 修复语法后重新运行 |

不要只把“终端没报错”当作成功：本节的验收证据是**实际出现你刚写的新句子**。

## 合上示例，独立写两句输出

在已初始化的独立练习目录，从空白 main.go 自己组织包声明、导入、入口和两次打印。第一句是“学习计划开始”，第二句是“今天写两句程序”。**不能复制整份例子再替换文字；先写完整预期，再把结构和语句写出来。**

保存并运行，终端应恰好显示两行，顺序与上面一致；两句不能挤在同一行。再交换你写的两条打印语句位置，预测顺序并核对。最后说明程序从哪个函数进入、哪两次调用产生了两行文字。

### 参考答案

main 中语句按顺序执行，每次 Println 结束时换行。交换两行调用的位置后，输出次序也交换；package 和 import 本身不会产生这两句文字。

下面是可直接替换的完整 `main.go`。在本节独立模块中保存后运行 `go run .`。

```go
package main

import "fmt"

func main() {
	fmt.Println("学习计划开始")
	fmt.Println("今天写两句程序")
}
```

预期结果：

```output
学习计划开始
今天写两句程序
```
