# 数组与下标

用固定长度数组保存三个分数，读取和修改一项。

## 多个同类型值放到一组里

前面用一个变量放一个分数。现在用数组放三个整数，`[3]int` 表示长度为 3、元素类型为 int；花括号里的三个值按顺序初始化。**下标是位置编号，从 0 开始；长度是元素总数，两者不同。**

| 日常称呼 | 代码下标 | 初始分数 |
| --- | --- | --- |
| 第一项 | `scores[0]` | 60 |
| 第二项 | `scores[1]` | 80 |
| 第三项 | `scores[2]` | 100 |

`[3]int` 和 `[4]int` 是不同的数组类型，不能只因为里面都有整数就直接赋值给彼此。没有写出初值的整数元素会得到零值 0。

### 就地练习：长度与末项下标

声明四项整数数组，写出长度、首项下标和末项下标。先预测只填两个初值时另外两项的值，再打印。

### 参考核对：长度与末项下标

长度4，下标0到3；未填整数项为0。下标4已经越界。

## 数组的初始化、比较与多维形式

`var a [3]int` 得到 `[0 0 0]`；`b := [...]int{1,2,3}` 让编译器按字面量推断长度，b 仍是固定的 [3]int。也可按位置初始化 `c := [4]int{1:10, 3:20}`，没写的位置为 0。

元素类型可比较时，同类型数组可以用 == 比较所有对应项；数组长度也必须一致。例如 `[2]int{1,2} == [2]int{1,2}` 为 true。`[2][3]int` 表示两项，每项本身是三个整数的数组，`matrix[1][2]` 先选第二行再选第三项。

数组作为函数参数也按值复制；切片并非同一种类型，下一节会对比它们的传递与共享成本。

### 就地练习：按位置初始化

建立 `[4]int{1:10,3:20}`，打印整组，再复制给另一个数组并修改副本下标1。

### 参考核对：按位置初始化

原数组为[0 10 0 20]；改副本不会改原来的普通整数项。

## 先运行一个小例子

在已初始化的独立 Go 练习目录中，把下面完整代码保存为 main.go。本节替换原文件，不在文件末尾追加另一份 main 函数。

```go
package main

import "fmt"

func main() {
	// [3]int 是固定三个整数；花括号按顺序提供初值。
	scores := [3]int{60, 80, 100}
	fmt.Println(scores[0])              // 下标 0 是第一项，不是“没有项”。
	scores[1] = 90                      // 只更新第二项，不改变数组长度。
	fmt.Println(scores[1], len(scores)) // len 数元素个数，结果仍是 3。
}
```

在这个目录的终端运行：

```sh
go run .
```

预期输出：

```output
60
90 3
```

## 逐步读懂这个例子

数组有3项，下标依次是0、1、2。scores[1]=90更新第二项，不改变长度。len(scores)返回元素个数，而不是最后一个下标。整个数组赋值会复制各项的值。

`scores[1] = 90` 发生之后，整组数据是 `[60 90 100]`，第一项仍为 60，长度仍为 3。`fmt.Println(scores[1], len(scores))` 输出两个值，中间有空格，读成“第二项 90、总共 3 项”。

赋值 `other := scores` 得到包含三个整数副本的另一个数组；改 `other[0]` 不会改 scores[0]。下一课的切片有不同的共享规则，不能把两者混在一起。

## 自己改一处再运行

把第三项改成95，打印第三项；说明为什么scores[3]不是第三项。

### 参考答案

第三项下标是 2。scores[3] 指向不存在的第四项；固定数组上这个常量下标会在编译时被拒绝。

下面是可直接替换的完整 `main.go`。在本节独立模块中保存后运行 `go run .`。

```go
package main

import "fmt"

func main() {
	scores := [3]int{60, 80, 100}
	scores[2] = 95
	fmt.Println(scores[2])
}
```

预期结果：

```output
95
```

## 越界错误能告诉你什么

若下标是变量，先判断 `index >= 0 && index < len(values)`，再访问。只检查小于长度会漏掉负下标。固定长度数组的常量越界通常在编译时发现；变量下标越界则可能等到运行时才 panic。两种情况都应修复下标来源，不是换一种打印方式。

## 检查访问范围

打印并修改第三项时使用下标 2。若直接写 `scores[3]`，编译器能看出这个固定下标越界，会拒绝运行。若下标来自变量且运行时越界，会出现 panic，也就是程序因无法继续安全执行而报错终止。

恢复范围后重新运行。能写出“有效下标满足 0 ≤ 下标 < len(scores)”并解释最后一个下标为何是 2，才算分清位置和数量。

## 合上参考，独立整理四项测量值

从空白 main.go 建立固定四项的整数测量记录，初值依次为11、12、13、14。自己声明数组，先读取第四项，再把第四项更新成24，输出数组长度和整组数据。

随后把更新后的数组赋给另一个变量，仅把副本第一项改成99。预期：第四项原为14，长度始终为4；原数组最后是 `[11 12 13 24]`，副本是 `[99 12 13 24]`。

**先写出第四项和末项以外位置的下标，再访问；四项数据不意味着有下标4。** 用自己的程序解释为何修改副本第一项不改原数组。

### 参考答案

先读取第四项再更新，所以第一行是 14。数组赋值复制四个整数，副本改首项后原数组保持 11；所有操作都没有改变数组类型中的长度 4。

下面是可直接替换的完整 `main.go`。在本节独立模块中保存后运行 `go run .`。

```go
package main

import "fmt"

func main() {
	measurements := [4]int{11, 12, 13, 14}
	fmt.Println(measurements[3])
	measurements[3] = 24
	fmt.Println(len(measurements), measurements)
	backup := measurements
	backup[0] = 99
	fmt.Println(measurements)
	fmt.Println(backup)
}
```

预期结果：

```output
14
4 [11 12 13 24]
[11 12 13 24]
[99 12 13 24]
```
